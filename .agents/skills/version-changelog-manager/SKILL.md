# Version & Changelog Manager (Release & SemVer Standard)

Цей скіл регламентує процес обліку релізів, версіонування та ведення історії змін у проєкті `my-quiz-local`.

## 1. Базова точка відліку та SemVer
- Поточна затверджена чиста базова версія: **`v6.9.2`**.
- Кожен наступний реліз збільшує номер версії відповідно до Semantic Versioning:
  - **Patch (`v6.9.X`):** виправлення помилок, точкові оптимізації, дрібні покращення UI.
  - **Minor (`v6.10.0`):** додавання нових значущих модулів або фіч (наприклад, окремі нові екрани або тренажери).
  - **Major (`v7.0.0`):** глобальний рефакторинг та кардинальна зміна архітектури.

## 2. Обов'язкова категоризація змін (Two-Category Rule)
Кожен запис в історії версій (`VERSION_HISTORY` у `scripts/main.js` та проектна документація) повинен обов'язково структуруватися за двома чіткими категоріями:
- `✨ Нові фічі та покращення` (Features & UX Enhancements)
- `🐛 Виправлені баги` (Bug Fixes & Stability)

Якщо реліз містить лише один тип змін, відповідна категорія все одно зазначається з відповідним маркером або описом.

## 3. Синхронізація точок версіонування (Release Checklist)
При будь-якому релізі обов'язково оновлюються:
1. Константа `APP_VERSION = "vX.X.X"` у `scripts/main.js`.
2. Масив `VERSION_HISTORY` у `scripts/main.js` (новий об'єкт додається на початок).
3. Бейдж версії в розмітці: `#app-version-tag` у `index.html` (наприклад, `<div class="version-tag" id="app-version-tag" ...>vX.X.X</div>`).
4. Повідомлення агента у відповіді користувачу із фіксацією рядка:
   `Нова версія: vX.X.X (зміни: ...)`
